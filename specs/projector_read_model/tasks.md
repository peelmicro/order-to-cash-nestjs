# `projector_read_model` — Tasks

> Work top to bottom. Tests are written **inside** each group, never at the end. Every task is small enough to verify before ticking. References: `requirements.md` (`PR1` – `PR29`, shared `R50` – `R55`), `design.md` (§ numbers below).
>
> **Three rules bind every task in this file.**
> 1. **Synchronise only on terminal or monotonic evidence** (design §10). This service is a race by construction; never poll for an intermediate status a correct system passes through, and never `sleep`.
> 2. **The fact-emission rule** (`CLAUDE.md` § Testing conventions) applies to the four branches of design §10.1. Group **H** is where you arm each deletion yourself and record the verbatim failure.
> 3. **`N10` (feature 21):** an assertion that a rolled-back or absent side effect did not happen proves **nothing** about whether it was attempted. Wherever a task says "no duplicate entry", it also requires observing the *attempt* — the `null` from `findOneAndUpdate`, or a counter on the post-apply callback — not only the document's final contents.

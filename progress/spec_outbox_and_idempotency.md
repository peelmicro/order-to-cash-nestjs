### 7.1 The amendment — open point 14 gains a parity guard (**OI12**)

**The gate's observation.** §3 row 14 resolves the "five components need this pattern, `CLAUDE.md` forbids a third shared runtime package" tension with per-service copies of an ~80-line pattern. The gate accepted the duplication and its reasoning, but observed that five hand-copied files drift, and that this pass's own **row 20** resolution had already invented the right instrument for exactly this shape of problem: a pure-text test that reads the committed artefacts of all three databases and asserts the `outbox`/`processed_events` statements agree, replacing a diff three reviewers had been doing by hand. The amendment is to apply that instrument a second time, to the pattern copies, so the duplication is guarded by a check rather than by discipline.

**What was decided, and why.**

| Decision | Resolution |
|---|---|
| **What is compared** | A **designated canonical copy** — the Orders pair, which `design.md` §6.3 already called "the reference implementation" — with every other MySQL write model's copy **byte-identical to it**, comments and whitespace included, after exactly **one** normalisation: the leading `//` banner is stripped from both sides. Whole-file byte identity was rejected because it forbids the one per-service difference worth having (a copy that says it is a copy and points at its canonical); a forgiving normalisation (strip comments, rename service tokens, compare ASTs) was rejected because every normalisation rule is a licence to drift, and the drift it would forgive first is a comment still asserting a rule the code has stopped following. |
| **The constraint that follows** | Byte-identity is only satisfiable if the pattern names no service, so the *test* becomes a *constraint on the code*: `processed-events.repository.ts` may not mention `OrdersDb` (it unwraps the opaque `TransactionContext` through D1's single `asDrizzleTx`), every import specifier must be one that resolves identically in every service tree (whitelisted in `design.md` §6.4 — satisfiable today, since all three services already export `processedEvents` from an identically-pathed file), and any prose that names a service moves into the banner. New task **G7**. |
| **Where the test lives** | `apps/orders/src/infrastructure/messaging/idempotent-consumer.parity.spec.ts` — **beside the canonical copy, not in `apps/seed`**. Row 20's claim on `apps/seed` is precise and does not extend here: seed is *"the one package that legitimately spans all three **databases**"*, and committed migration SQL is a database artefact seed genuinely depends on. The pattern copies are not database artefacts and the set is not the seeded three — it is five components, two of which (`projector`, `notifications`) `apps/seed` does not seed, does not import and has no relationship with. The canonical owns its guard: a developer editing `idempotent-consumer.ts` gets a red spec in the same directory as the mistake. |
| **How it stays pure text** | `node:fs` only, repo root resolved by walking up from `import.meta.url` to the directory holding `pnpm-workspace.yaml`, apps enumerated with `readdirSync('apps')` — no glob package, **no new dependency** (§3 row 26's package table is unchanged), no `tsconfig` include, no Docker. It runs inside `pnpm quality`, exactly as row 20's test does. |
| **Behaviour while only the Orders copy exists** | Four cases, of which two are meaningful **today** and two arm themselves structurally, so the guard cannot pass silently forever at n = 1: (1) *parity* over the copies — one member today, arming at feature 17; (2) *canonical portability* — non-vacuous now, and the anti-vacuity case: it fails the day someone writes `OrdersDb` or a non-portable import into the pattern; (3) *census* — an app with a MySQL `processed_events` schema **and** any `@EventPattern` under `src` must carry a copy, which turns red the moment a service gains a consumer without the pattern; (4) *variants* — a copy in an app **without** a MySQL ledger (the projector's Mongo dedup, feature 23's choice) is never compared, but must cite the canonical path and carry a `Divergence:` line. The copy/variant discriminator is read from the filesystem, never from a hand-maintained list of app names, because a registry that must be edited when a copy is added is a registry someone forgets to edit. |
| **Promotion** | **`OI12` is not a promotion candidate**, and `requirements.md` §5 now says so. It guards a duplication that exists only because #7's `CLAUDE.md` forbids a third shared runtime package; #8 can share one project and #9 one module, leaving them nothing to keep in parity. The promotion list stays at four (`OI1`, `OI2`, `OI4`+`OI5`, `OI10`). |
